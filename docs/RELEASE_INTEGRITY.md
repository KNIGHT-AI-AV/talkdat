# Release integrity

Talk DAT! publishes four Windows release assets:

- `Talk-Dat-Setup.exe`
- `Talk-Dat-Windows-Portable.zip`
- `SHA256SUMS.txt`
- `RELEASE-RECEIPT.json`

The receipt is generated by the same clean Windows CI job that builds and tests the
installer. It identifies the repository, tag, exact Git commit, version, UTC build
time, runner OS, Python version, Artifact Signing state, asset sizes, and SHA256
hashes.

Release CI refuses to build under a tag that points to a different commit. After
publication, a separate job downloads the installer through Talk DAT!'s own updater,
downloads the public receipt, compares the installer size and SHA256 to the receipt,
then exercises install, same-version replacement, and uninstall.

For receipt-enabled releases, the app validates that the receipt belongs to
`KNIGHT-AI-AV/talk-dat-releases`, matches the selected tag, identifies an exact
40-character private-source commit, and binds the setup EXE to its published size and SHA256. It verifies those bytes after download and
once more immediately before launch. If the receipt says Artifact Signing was
enabled, the updater also requires Windows to report a valid Authenticode publisher
signature. The installer writes size/SHA256 receipts for installed files and checks
them before the staged replacement commits, so a failed repair verification rolls
back to the previous install. Until a public receipt declares signing and the
download passes that signature gate, Windows may still label the release as coming
from an unknown publisher.

## Manual verification

From PowerShell in the folder containing the downloaded files:

```powershell
Get-FileHash -Algorithm SHA256 .\Talk-Dat-Setup.exe
Get-Content .\SHA256SUMS.txt
Get-Content .\RELEASE-RECEIPT.json
```

The setup hash must match both `SHA256SUMS.txt` and the installer entry in the JSON
receipt. Start downloads from `https://talkdat.knightaiav.com/`; the page and
in-app updater resolve the same binary-only Knight AI+AV release channel.
